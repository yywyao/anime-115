# 使用与维护指南

## 115 与 AList

网站使用本地账号。在管理员设置中验证已有的第三方 115 Cookie（CK），再保存转存目录。Cookie 验证与目录配置独立进行，同一份 Cookie 用于 115 和 AList。Cookie 到期后，请从原客户端获取新凭据并更新设置。

默认部署包含 AList 和 Sonarr。应用自动取得 AList 管理令牌，115 存储复用设置中保存的 CK。AList 挂载信息位于临时内存盘，重启后会从加密配置恢复同一个专用目录。

需要使用已有 AList 时，在设置的 AList 区域切换「自定义」，填写地址、用户名以及管理员密码或管理令牌，保存时会验证连接。相同地址及用户名可以留空凭据以沿用已保存值。更改服务地址需要填写对应服务的凭据。选择「自动」并保存即可恢复本部署的服务。

## 存储目录与迁移

系统使用独立的转存根目录，默认 `anime`。目录名称可自定义，只接受 115 根目录下的文件夹名称。修改名称时按原目录 ID 更名，已有文件与任务保留。若目录已被外部改名，重新保存目录设置即可核对并恢复；原目录已删除或移出根目录时仍会停止操作。其他同名目录不会被接管或合并，可换一个名称后保存。请勿手动修改 AList 专用挂载；日常网盘文件不属于任务管理范围。

关联作品的转存结果按以下结构整理，同一系列只有明确关联的来源 ID 相同时才会共用文件夹。

```text
anime/
└── 系列名/
    ├── 系列名 - S01E01 [字幕组] [简日] [1080p].mkv
    └── 系列名 - S02E01 [字幕组] [简日] [1080p].mkv
```

转存期间使用独立的临时任务目录。改名完成后按文件 ID 和大小校验，移入系列目录，仅清理空的任务目录。重复文件名不会覆盖。旧任务中未关联作品的手动磁力保留隔离目录。

VPS 下载采用相同的系列命名，根目录固定为 `runtime/app/library/anime/`。旧版 `mikan` 下载目录支持迁移至 `anime`，同步更新任务路径并保留原文件。目标位置存在其他同名目录时停止迁移；中断后按目录身份核对并继续。不会覆盖文件或仅凭大小相同收录已有文件。

## 转存与入库

在资源弹窗先选择「转存至 115」或「下载到 VPS」。两者分别核对库存、生成清单并跟踪任务；115 已有而 VPS 没有的剧集可直接复用云端文件，通过 AList 下载，不再创建第二个云下载任务。转存、改名及整理尚未完成时，VPS 任务会自动等待。

| 方式 | 显示和处理的内容 |
| --- | --- |
| 补缺集 | 已播出、目标位置缺少、且没有正在处理的剧集 |
| 收集全部 | 当前资源中目标位置尚未拥有的剧集；每集按所选偏好挑选一份 |
| 洗版 | 目标位置已有剧集的另一个指定版本；须选择字幕组、字幕或分辨率，保留原文件 |

资源数量与实际集数分别统计。

支持组合筛选、分组选择与逐项选择。资源清单按偏好生成，库存或资源发生变化时需重新确认。

合集解析为明确的集号范围。补缺或收集全部不会提交包含已有剧集的混合集合，避免重复转存；未知集号不会猜测入库。已下载文件按大小和路径校验后计入 VPS 库存。

### 多磁力导入

在任务页的「磁力链接」中粘贴一个或多个链接，点击「读取链接」。系统解析磁力名称中的字幕组、季集号、字幕与分辨率，合并重复 BTIH，并按名称与字幕组汇总，可整组选取或逐项勾选。最后选择转存至 115 或下载到 VPS 并提交。

没有 `dn` 名称时，优先使用同一 BTIH 的本地任务或可核验的蜜柑缓存名称；找不到则保留未命名与未知集号。分组用于选择，不会只凭相似名称自动确认作品。可展开「关联动漫」，搜索并明确选择作品及季度，随后与首页、RSS 使用同一集号去重记录。同一磁力名称冲突时需先核对并移除冲突链接，不会按错误标签自动改名。

## RSS 订阅

先搜索并选择动漫，名称、季号和已确认的 TMDB ID 自动填入；目录没有时可搜索 TMDB 并明确选择对应季度。不会把相似标题自动当作身份关联。然后选择蜜柑、动漫花园、Nyaa 或 ACG.RIP，系统生成对应订阅。也可展开「使用 RSS 链接」，粘贴上述网站受支持的 RSS、搜索或作品链接进行转换。

蜜柑支持作品、字幕组和个人 MyBangumi RSS。其他来源须先选择已确认的 TMDB 作品及季度，资源标题还要通过别名和明确季号校验。季号、集号或作品不明确时跳过并展示原因。默认仅处理创建之后的新资源；下载历史资源需明确勾选「同时收集现有剧集」。

字幕组右侧「追新」会绑定该组的蜜柑 RSS，并带入当前分辨率和字幕筛选。首页追新与 RSS 共用作品身份、实际库存和持久化剧集记录，同一集的镜像资源不会重复转存或下载。相同作品的多个来源会并入追新规则。默认每分钟检查 RSS，新建的单组追新匹配后立即转存。检查间隔和优选等待可在追新管理中修改。

| 规则 | 行为 |
| --- | --- |
| 字幕组 | 可设置准入列表及排序；未选择时允许全部 |
| 字幕版本及分辨率 | 根据发布信息识别，未知标签保留未知 |
| 关键词 | 必含词全部匹配，排除词任一匹配；使用字面文本 |
| 集数 | 可设集数范围、合集开关和偏移 |
| 优选等待 | 等待期内候选统一排序，完成转存后不自动替换 |
| 去重 | 支持每集、每集每种字幕或资源哈希去重 |
| 下载到 VPS | 显式开启后，转存就绪时另建 VPS 下载任务 |

使用预览检查规则不会创建云任务。暂停或取消订阅保留已转存文件；未连接 115 时可保存订阅规则，待连接后处理。

## 云端文件命名

新建追新和资源转存默认开启自动改名，已有追新保留原设置。也可在已完成任务中预览并确认手动改名。例如：

```text
作品名 - S02E03 [字幕组] [简日] [1080p].mkv
```

季集号无法确认、集数冲突或文件重名时保留原名，在任务中核对改名预览，确认后继续整理及 VPS 下载。集号偏移仅适用于无显式季号的总集数，例如总集数 22 对应 S02E09 时偏移为 -13。配套字幕随视频改名。改名与文件整理分别校验，均不会覆盖已有文件；整理中断后按原文件 ID 核对并继续。

Sonarr 随默认部署启动，应用自动设置服务地址，并从本部署凭据派生独立的 API Key。校对实例使用临时配置，访问范围为作品查找、季集解析和状态检查。需要使用已有 Sonarr 时，在设置中选择「自定义」并填写地址和 API Key，保存时自动检测可用的 API 版本。

应用按明确 TVDB ID 调用 Sonarr 的 `series/lookup` 和 `parse` 接口校对季集号。明确的冲突会进入复核。解析缺失时，仅在 TMDB 中有唯一对应季集记录、且发行集号一致时进行站内改名。

## 元数据

管理员可在设置中配置 TMDB API Key 或 Read Access Token。未配置时仍可使用本地公开目录。后台优先更新下一季度和本季，历史目录从新到旧分批刷新。上游失败时保留已有资料。封面、背景图、标题标志及评分按已确认的作品和季度关联，缺失信息保持缺失。来源及署名参见 [目录数据声明](../NOTICE-Catalog-Data.md)。

## 原生运行

需要 Python 3.12+。原生运行可在设置中自定义已有 AList 和 Sonarr，或通过环境变量提供本机服务的启动凭据。自动启动完整服务使用 `python3 tools/start.py`。环境变量参见 [应用配置](../mikan115/config.py)。

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
export ALIST_URL=http://127.0.0.1:5244
python run.py
```

应用默认监听本机 8788 端口。已有静态构建可直接运行，修改前端后再重新构建。

## 数据维护

Docker 部署的应用数据位于 `runtime/app`，其中 `library` 存放下载到 VPS 的文件。备份数据库时同时保留 `secret.key` 和私有 `.env`。旧版升级前可保留原 `runtime/alist` 的离线备份。分发包使用项目的公开文件。 [打包脚本](../tools/package.py)

## 内置程序更新

以 `python run.py` 或默认 Docker Compose 启动即包含更新监督组件。旧的直接 `Application`/`server` 启动方式需改用此入口一次。管理员在「设置 → 系统更新」中检查、下载并应用更新，可开启自动检查和自动更新。下载期间网站仍可使用，切换期间短暂不可用。

更新源固定为 `yywyao/anime-115` 的 `main`，读取明确提交的完整 Git 目录，并验证每个文件的 Git blob 校验值。GitHub API 限流或暂不可用时，自动读取仓库内的发布清单，仍按明确提交下载并逐文件校验，无需 GitHub Token。仅下载发生变化的程序文件；相同文件复用，删除的代码不进入新版本。代码存放于私有数据目录的 `updates/versions`，不改动原始 Git 工作目录。固定版本依赖如有变更，会安装至独立版本的依赖目录。

应用等待当前写入操作结束，再停止旧工作进程并备份 SQLite。新版本启动检查通过前不执行追新或下载；启动失败或中断会恢复旧代码和切换前数据库。管理员主动选择「恢复上一版」只恢复程序，并保留更新后新增的业务数据；若旧版无法使用当前数据库，恢复操作会回退到操作前版本。

私有 `.env`、`secret.key`、CK、账号和下载文件不属于代码更新内容。`updates/backups` 含私有数据库备份，应与其他运行数据一起保护和备份，不要放入 Git。基础镜像、AList、Sonarr 或 Compose 部署配置的更新仍需通过部署命令完成；程序更新不访问 Docker 管理接口。

目录迁移后，仅允许恢复支持 `anime` 布局的版本；不兼容的旧版会被阻止，以免路径记录失效。

## 开发者发布

发布代码后，运行 `python tools/build_update_manifest.py` 为当前已提交版本生成备用清单，再提交 `seed/update-manifest.json` 并一同推送。清单只读取 Git 中已提交的程序文件，不读取运行目录；下一次发布会替换该清单。
